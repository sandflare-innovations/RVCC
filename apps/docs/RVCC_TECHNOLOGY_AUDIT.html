2 What We Did Right vs. What Needs Attention
✓ WHAT WE DID RIGHT (STRENGTHS)
1. Discrete Turborepo App Isolation
Splitting Marketing, Vendor, and Admin into separate Next.js apps prevents administrative code and sensitive business logic from leaking into public bundles, while allowing autonomous team deployments.
Impact: Enhanced security and optimized frontend bundle sizes.
2. Edge Compute with Hono & Workers
Deploying the unified API (`apps/api`) on Cloudflare Workers using Hono delivers sub-millisecond cold starts and distributed edge execution with zero server maintenance overhead.
Impact: Global performance with near-zero infrastructure cost.
3. Cloudflare R2 Storage without Egress Fees
Serving heavy supplier documents, certificates, and media through Cloudflare R2 eliminates AWS S3 egress penalties while maintaining full S3 API compatibility.
Impact: 100% predictable, low-cost asset hosting.
4. Modern UI Stack (Tailwind v4 + Framer)
Using Tailwind CSS v4 alongside Framer Motion and Lenis gives the platform modern micro-interactions, smooth scrolling, and a premium aesthetic without heavy CSS frameworks.
Impact: State-of-the-art user experience across devices.
⚠️ WHAT IS WRONG / RISKY (VULNERABILITIES)
1. Direct Edge DB Connections (Connection Storms)
Cloudflare Workers connecting directly to standard PostgreSQL via `postgres.js` will exhaust max_connections under burst traffic, triggering intermittent 503 Service Unavailable errors.
Fix: Connect via Cloudflare Hyperdrive or PgBouncer.
2. No Shared Packages (`packages/` folder)
All 4 apps duplicate TypeScript types, DTOs, and Zod schemas independently. When an enquiry or vendor data model changes, developers must manually synchronize code across 3 repositories.
Fix: Extract `packages/types` and `packages/schemas`.
3. Raw SQL Queries (Lack of ORM Type Safety)
Writing hand-crafted SQL strings inside API route handlers introduces maintenance friction, schema drift, and increases the potential risk of SQL syntax bugs during migrations.
Fix: Adopt Drizzle ORM for zero-overhead type-safe queries.
4. Heavy SSR Overkill in Admin & Vendor Apps
Next.js App Router with server-side rendering is ideal for the public marketing site (`web`), but adds proxy and hydration complexity for internal, authenticated backoffices.
Fix: Leverage React Query (TanStack Query) for client caching.
3 Strategic Improvements & Priority Roadmap
Priority Initiative Action Plan Expected Result
P0 - Urgent Connection Pooler / Hyperdrive Route Cloudflare Workers database traffic through Cloudflare Hyperdrive or Supabase/Neon transaction pooling. Eliminates DB connection exhaustion & crashes at peak load.
P0 - Urgent Extract Shared Monorepo Packages Create packages/schemas and packages/types to share Zod validation rules and DTOs across Web, Admin, and API. Zero duplicate validation logic; 100% type sync between frontend & backend.
P1 - High Drizzle ORM Migration Replace raw SQL strings in apps/api/src/modules/ with Drizzle schema declarations and queries. Automatic migrations, type-safe database queries, and easier refactoring.
P1 - High TanStack Query (React Query) Implement React Query in apps/admin and apps/vendor for data fetching, table pagination, and optimistic updates. Instant dashboard navigation, background data sync, and cleaner UI code.
P2 - Medium Centralized Telemetry & Sentry Integrate edge error monitoring (Sentry / Axiom) across Cloudflare Workers and Next.js frontends. Real-time alerts on failed enquiry submissions or API exceptions.
